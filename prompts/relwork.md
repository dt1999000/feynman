Write the related work and introduction for the LaTeX project and instructions in: $@

## Inputs

- **Project** — the first argument is the path to the user's LaTeX project, such as a thesis or venue template they have started. Without a path, use the current directory when it holds a root file.
- **Brief** — the work's name, a description of the work, and seed papers. Read it from `brief=<file>` when given, otherwise from `<project>/feynman-brief.md`. Seed papers may be DOIs, arXiv IDs, URLs, or titles.
- **Language** — `lang=en` or `lang=de` in the arguments wins, then `Language:` in the brief, then the document's language option (`ngerman` in the class options or babel `main=ngerman` means German). Write the sections in that language. Search the literature in English and German regardless of the writing language.
- **Instructions** — any other text in the arguments, such as "related work only" or "at most four pages".

If the brief is missing or has no name or description, ask the user once for the work's name, a description of a few sentences, any seed papers, and the language, and offer to save their answer to `<project>/feynman-brief.md`. This is the only point where you wait for the user.

## Workflow

1. **Read the project and its guidance.** Find the root file: the file with `\documentclass`, which may be `main.tex` or a template such as `main.tex.em`. Follow `\input`/`\include` to the chapter files. Read the title, abstracts, method, and results if they hold real content, and note the citation package, the bibliography file, macros, and the document language. Derive the slug from the work's name.
   - Collect every piece of **writing guidance** the template gives for the target chapters: instruction paragraphs, question lists, "self-monitoring" checks, notes, and guidance hidden in placeholder bibliography entries or the README. Write it as a numbered rubric to `outputs/.plans/<slug>-rubric.md`, one item per question or requirement (R1, R2, ...), each with its source file and line. When guidance is given in two languages, merge the two versions into one item. Add these items whatever the template says: R-relevance (the sections are about the described work) and R-gap (the sections state a specific research gap the work fills).
   - Write the plan to `outputs/.plans/<slug>.md`: project path, root file, language, target files, a 3–5 sentence summary of the work from the brief, the seed papers, 3–6 related-work themes, each with search terms in English and German, length limits, and a task ledger. Summarize the plan to the user in a few lines and continue.
2. **Embed and rank the starting point.** Resolve each seed paper to a DOI or arXiv ID with `feynman_science_database_search` and get its abstract. Call `feynman_embed` with `action=search` and the work description to find papers embedded in earlier runs. Then call it with `action=rank` on the seeds and those library hits, using the work description as the query. Use the ranking to sharpen the themes and search terms in the plan. Embeddings are cached on disk; never embed the same text twice on purpose.
3. **Gather in English and German.** Spawn one `researcher` per theme in parallel, each with `output` set to `outputs/.drafts/<slug>-research-<theme>.md`. Tell each researcher to:
   - search with both the English and the German terms: `openalex_search_works:<terms> language=de` for German-language work; Semantic Scholar and OpenAlex in English; and web search for German theses, dissertations, and project reports (for example university repositories such as TUprints, and the DNB catalog);
   - start from the seed papers and expand one hop through the citation graph of the closest ones (`openalex_references`, `openalex_citations`);
   - name the main international conferences and journals of the field and the research groups that lead it, nationally (in Germany) and internationally;
   - record each paper's title, year, language, first author, DOI or arXiv ID, abstract, and its relation to the work (`builds-on`, `competes-with`, or `background`), and append one JSON line per paper (`{"id", "title", "text": title + abstract, "lang", "relation", "theme"}`) to `outputs/.drafts/<slug>-research-<theme>.jsonl`.
4. **Rank and select.** Concatenate the `.jsonl` files into `outputs/.drafts/<slug>-candidates.jsonl` and call `feynman_embed` with `action=rank`, `file` set to that file, and the work description as the query. Merge papers flagged `nearDuplicateOf`, such as a German report and its English paper; cite the version the reader can get best, usually the peer-reviewed one. Read the top-ranked papers and the user's seed papers before selecting. Keep every seed paper unless it is clearly off-topic, and say so if you drop one. Select the papers the sections will cite, usually 25–60 for a thesis, covering foundations, the main developments, and the current state of research, as well as the direct competitors. Record the selection, scores, and reasons in the plan.
5. **Find the research gap.** Write `outputs/<slug>-gaps.md`:
   - a coverage table: the selected approaches as rows, and the dimensions that matter for the described work as columns (problem setting, assumptions, method, evaluation, platform);
   - two to four candidate gaps, each stating what is missing, which papers come closest (with keys), and how the described work would fill it;
   - a **novelty check** for each candidate: run at least two targeted searches that try to find work that already fills the gap, in English and in German, and rank the hits against the gap statement with `feynman_embed`. Record the closest work found and label the candidate `open`, `partially addressed`, or `already addressed`. Drop candidates that are already addressed.
   Choose the primary gap: the open or partially addressed gap that best fits the description. Never present a gap as open without its novelty check.
6. **Bibliography.** Call `feynman_bibtex` with the selected DOIs and arXiv IDs and the project's `.bib` file as `output`. Compare each returned title, year, and first author with the selection. Look failed identifiers up again; drop papers that still fail and note them in the plan. Leave the template's own placeholder entries in the file.
7. **Write.** Before writing, copy each target chapter file to `<name>.template.tex` next to it unless that backup exists. Spawn the `latex-writer` with the project path, the language, the target files, the brief, the plan, the rubric, the gap file, the research files, the `.bib` path and the keys it may cite, and the user's instructions. Write the related work first, then the introduction, so the introduction's gap and goal match the related work. Every rubric item must be answered explicitly in the text.
8. **Check citations.** Spawn the `verifier` on the written `.tex` files with these instructions in the task: this is a LaTeX artifact, so keep `\cite`-family keys and do not convert them to `[n]` or add a Sources section; check that every cited key exists in the `.bib`; check against the research files that each citation supports its sentence; replace an unsupported citation with a supported key or a `% TODO(feynman)` note; and write its findings to `outputs/<slug>-verification.md`.
9. **Score.** First call `feynman_embed` with `action=rank`, each paragraph of the written sections as an item (id = file and paragraph number), and the work description as the query; save the result to `outputs/.drafts/<slug>-paragraph-relevance.json`. Then spawn the `reviewer` with the sections, the rubric, the brief, the gap file, and that ranking, to write `outputs/<slug>-scorecard.md`: a table with a score, the passage that earns it, and what is missing for each item:
   - every rubric item: 0 (not answered), 1 (partly or only implicitly answered), or 2 (explicitly and clearly answered);
   - relevance to the work description, 1–5, using the paragraph ranking as supporting evidence and listing paragraphs that score far below the rest;
   - novelty of the stated gap, 1–5, judged from the novelty check in the gap file;
   - scientific writing quality in the chosen language, 1–5: precise claims, fair treatment of competing work, and logical flow from the state of research to the gap to the goal.
   If any rubric item scores 0, relevance is below 4, or novelty is below 3, send the scorecard to the `latex-writer` for one revision, rerun the citation check if citations changed, and score again. Keep both scorecards in the file.
10. **Deliver.** If `latexmk`, `lualatex`, or `tectonic` is installed, compile into a scratch directory (for example `latexmk -lualatex -outdir=.feynman-build`) and report the result; otherwise say it was not compiled. If the root is a template such as `main.tex.em`, say how the user builds it instead. Write `outputs/<slug>.provenance.md` with: the date, the project path and language, papers found vs. selected vs. cited (English and German counts), embedding cache hits vs. new embeddings, identifiers that failed to resolve, the primary gap and its novelty label, the final scores, verification status, compile status, and the intermediate files used. Tell the user which files changed and where the backups are, any preamble change they need (for example switching the class option to `ngerman` for a German thesis), the final scores, and every `% TODO(feynman)` left. Before you stop, verify on disk that the section files, the `.bib`, the gap file, the scorecard, and the provenance file exist.
